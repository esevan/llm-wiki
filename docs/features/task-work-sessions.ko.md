# Task 작업 세션

위임된 Codex 작업의 출력은 상위 실행과 분리됩니다. 활성 실행에 연결할 수 없는 승인은 상위 실행에 표시하지 않고 거부합니다.

**한국어** | [English](task-work-sessions.md)

Task 세부 정보의 세션 탭은 집중해서 진행한 내용을 Task의 정식 정의와 Work Log에서 분리해 보존합니다. 왼쪽 레일에는 저장된 세션이 표시되고 대화가 주 작업 영역으로 유지됩니다. Task를 여는 것만으로는 세션 기록을 불러오거나 Codex 세션 서비스를 시작하지 않으며, **세션**을 선택한 뒤에만 해당 작업을 시작합니다. Task를 여는 것만으로 세션이 생기지 않습니다. 필요할 때 **새 세션**을 선택하거나 **Codex 세션 연결**을 선택해 같은 로컬 Codex 홈에 있는 Codex CLI, Codex 앱 서버 또는 VS Code 확장의 저장된 대화를 연결할 수 있습니다. 연결은 한 번의 동작으로 Task 세션을 만들 수 있으며 제공자 작업을 시작하거나 재개하지 않습니다.

스트리밍 중에는 현재 답변만 가벼운 텍스트로 갱신하고, 완료된 과거 답변을 조각마다 다시 파싱하지 않습니다. 성공적으로 답변이 완료되면 해당 답변 전체를 최종 Markdown으로 한 번 전환하고 150ms 페이드를 표시합니다. 타이핑을 다시 재생하거나 재진입한 과거 답변을 애니메이션 처리하지 않습니다. 모션 줄이기 설정에서는 페이드를 사용하지 않습니다. 현재 텍스트를 선택하면 선택을 해제할 때까지 표시 내용을 유지하고, 선택 중에는 대화를 강제로 스크롤하지 않습니다.

열린 세션 화면은 해제 가능한 구독 하나만 유지합니다. 화면을 닫거나 전환하면 공급자 작업은 계속하면서 구독을 해제하고, 준비나 추가 Run은 구독을 늘리지 않습니다. 첫 내용과 저장된 실행 상태 변경은 즉시 전달합니다. 중간 스트림 상태는 32ms 단위로 병합하며, 구독마다 수신 확인을 기다리는 중간 페이로드 한 건과 최신 상태로 교체 가능한 대기 신호 한 건만 둡니다. 완료·오류·취소·승인 상태는 이 병합으로 버리지 않습니다. 최종 답변이 없으면 마지막 제한된 텍스트 조각을 유지합니다. 지연 복구를 위해 최근 종료된 실행의 조각을 최대 32건 메모리에만 유지하며, 이를 새 저장 보고서로 만들지는 않습니다.

세션 영역은 창이 커지면 Task 대화상자의 가용 너비에 맞춰 함께 넓어집니다. 세션 목록과 대화 안쪽 여백은 유지하며, 좁은 화면에서는 기존처럼 목록이 대화 위로 이동합니다.

각 세션은 대화 형태의 사용자 메모, 메모별 최대 10MB의 선택적 파일 하나, 세션 제목과 실행 설정을 저장합니다. 붙여 넣은 이미지는 저장 전에 미리 보이며, 저장된 이미지는 다시 볼 수 있고 모든 첨부 파일을 다운로드할 수 있습니다. 저장에 실패하면 메모와 첨부를 입력창에 유지해 다시 시도할 수 있습니다. 저장된 기록은 앱을 다시 시작해도 복원됩니다. 저장하지 않은 초안은 Task 세부 정보를 열어 둔 동안 유지되지만 앱을 다시 시작하면 복원되지 않습니다.

대화에는 사용자 메시지, 완료 후 Markdown으로 표시되는 Codex 본문, 도구 활동이 제공자 순서대로 나타납니다. 중복된 최종 본문은 한 번만 표시합니다. 명령은 간결한 행으로 표시되고 필요할 때 서식이 보존된 제한 높이의 출력을 열어 볼 수 있습니다. 대기 중, 실행 중, 응답 필요 상태도 분명히 표시됩니다. Task 맥락과 실행 설정은 대화 아래의 접을 수 있는 영역에서 확인할 수 있습니다. 맥락은 현재 Task와 참조를 읽되 Task 사본을 따로 저장하지 않으며 다른 Task의 세션을 포함하지 않습니다.

저장되어 있고 실행 중이 아니며 다른 Task가 소유하지 않은 Codex 대화만 연결할 수 있습니다. 이미 메모나 실행 기록이 있는 로컬 대상에는 관계없는 기록을 연결할 수 없습니다. 이 제한은 서로 다른 두 기록이 조용히 합쳐지는 일을 막습니다.

제공자, 모델, 승인 검토자, 프로젝트 폴더 경로는 세션마다 저장됩니다. **대화 준비**는 정확한 세션을 Codex에 연결하고 실제 설정을 확인하지만 작업을 시작하거나 실행 기록을 만들지는 않습니다. 이후 **설정 확인**으로 결과를 다시 확인할 수 있습니다. **메모 저장**은 메모와 첨부만 기록합니다. **Codex로 실행**은 별도의 명시 동작으로, Codex가 시작되기 전에 변경 불가능한 실행 기록 하나와 연결된 Work Log 행 하나를 저장합니다. 이후 실행은 이전 대화를 다시 보내지 않고 같은 세션의 정확한 Codex 대화를 이어갑니다.

프로젝트 폴더는 직접 입력하거나 native **찾아보기** 폴더 선택기로 고를 수 있고, 최근 저장된 세션 폴더 최대 10개에서 다시 선택할 수 있습니다. 찾아보기는 경로만 반환하며 Vault를 변경하지 않습니다. 작업이 시작되기 전 Codex 준비와 실행 단계에서 폴더를 다시 검증합니다. 실행 지침은 파일 탐색을 해당 프로젝트 폴더 안으로 제한하고 더 넓은 외부 경로를 검색하기 전에 명시적 승인을 요구합니다. 이는 운영체제 샌드박스가 아니라 지침 경계입니다.

실행은 연결된 Codex 기록과 함께 실제 시간 순서로 대화에 나타납니다. 이전 실행을 선택해도 현재 실행의 상태, 중지 동작, 승인, 질문은 계속 표시됩니다. 실시간 Codex 응답은 대화에서 바로 읽을 수 있고 명령 출력과 구현 근거는 입력창을 가리지 않도록 펼쳐 보는 형태로 유지됩니다. 많은 업데이트가 한꺼번에 도착해도 제공자 순서대로 처리하므로 출력 급증이 보존된 결과를 이벤트 전달 오류로 바꾸지 않습니다. Work Log 동기화 상태도 제공자 실행 결과와 별도로 표시됩니다. 중지는 인터럽트를 요청할 뿐이며 최종 제공자 상태가 완료·실패·취소를 결정합니다. 실패·취소·중단·결과 불확실 상태의 실행은 근거를 그대로 유지하며 저장된 시도 옆에 **실행 재시도**를 표시합니다. 재시도는 이전 지시와 원본 실행 연결을 사용해 별도 실행을 만들며 현재 입력창 초안과 첨부는 보내지 않습니다. 중단되었거나 결과가 불확실하면 작업이 이미 수행되었을 수 있으므로 재시도 전에 저장된 근거를 확인해야 합니다. 실행 설정을 준비했고 다른 실행이 진행 중이지 않을 때만 재시도할 수 있습니다. 재시도 응답을 받지 못한 경우 같은 동작은 동일한 작업 ID를 사용해 의도하지 않은 중복 실행을 막습니다. **지시 다시 사용**은 별도 동작으로, 입력창이 비어 있을 때만 이전 지시를 불러오며 다른 초안을 덮어쓰지 않습니다.

실행 중에도 입력창을 사용할 수 있습니다. **Enter**를 누르면 기본 **Codex로 실행** 동작을 사용하고 **Shift+Enter**를 누르면 줄을 바꿉니다. 한국어를 비롯한 IME 조합을 확정하는 Enter는 전송하지 않습니다. **메모 저장**은 Codex를 호출하지 않고 로컬 맥락을 기록합니다. 초안 첨부에는 실행 준비 또는 현재 실행과 함께 전송 중인지 표시됩니다. 실행 제출에 성공하면 첨부 미리보기를 비우고, 제출에 실패하면 다시 시도할 수 있도록 첨부를 유지합니다. 실행에 첨부한 이미지는 Codex로 전달되며, 메모로 저장된 첨부 파일은 세션 기록에 남아 나중에 다운로드할 수 있습니다.

정식 승인은 Codex가 보낸 실제 선택지만 제공합니다. 구조화된 질문은 비밀값이 아닌 답변을 선택하거나 입력한 뒤 한 번 명시적으로 제출해야 합니다. 오래된 요청은 비활성화되고 실패한 답변은 다시 시도할 수 있게 유지됩니다. Work Log 실행 블록은 정확한 세션과 실행으로 돌아갑니다. Codex 실행은 Task를 완료하거나 Problem을 해결하거나 Knowledge를 발행하지 않습니다. 전체 경계는 [기능 명세](../../specs/014-task-codex-execution/spec.md)를 참고하세요.

Run이 종료 상태에 도달하면 Work Log에서 읽기 쉬운 **실행 요약**를 볼 수 있습니다. 저장된 최종 보고서를 우선하며, 완료된 명령·파일·확인 근거는 보고서의 중요한 내용을 뒷받침하거나 보완하거나 반박할 때만 표시합니다. 각 주장은 제안·결정·시도·수행·관찰·검증 중 어떤 상태인지 구분하고 정확한 저장 출처를 제공합니다. 최종 보고서가 없으면 결정이나 성공 결과를 만들어 내지 않고 확인된 사실만 표시합니다. 정리 화면에서 원본 Run도 계속 확인할 수 있습니다.

같은 검증 결과는 모델을 다시 호출하지 않고 Task 과정의 **현재 결정과 근거**를 업데이트합니다. 명시적으로 저장된 결정만 채택·대체·철회·미해결 주제 상태가 될 수 있으며 일반적인 AI 문장은 사용자 결정으로 취급하지 않습니다. 노드 상세는 미리 저장된 로컬 데이터로 열리고 원본 이벤트 흐름은 별도로 유지됩니다. 출처가 바뀌면 마지막 정상 보기를 오래됨 상태로 계속 보여 주면서 내구성 있는 갱신 작업을 실행합니다. 일시적 실패는 제한된 작업 정책 안에서 자동 재시도하며, 모두 실패한 뒤에는 원래 Codex Run을 다시 실행하지 않고 작업을 명시적으로 재시도할 수 있습니다.

**사용자에게 묻기**는 승인을 사용자에게 전달합니다. **자동 검토**는 명시적으로 새로 선택해야 하며 Codex의 기존 승인 정책과 샌드박스를 유지합니다. 이전에 저장된 자동 승인 선호만으로 권한을 부여하지 않습니다.

세션을 사용해도 Task를 완료·재개하지 않습니다. 메모 저장은 AI를 호출하지 않습니다.

외부 세션 목록과 연결된 기록은 같은 로컬 Codex 홈에서 가져오는 페이지 단위 스냅샷입니다. 기본적으로 LLM Wiki는 Codex의 일반 로컬 홈(`~/.codex`)을 그대로 사용하므로 Codex와 VS Code 확장에서 저장한 대화가 연결 목록에 보입니다. 의도적으로 분리된 저장소가 필요한 경우에만 **AI 설정**에서 **LLM Wiki에 다른 Codex home 사용**을 선택하세요. 폴더는 이미 존재해야 하며, 선택을 적용하려면 LLM Wiki를 다시 시작해야 합니다. **더 불러오기**로 대화 목록이나 이전 턴을 추가로 가져올 수 있습니다. 연결된 세션을 열면 정확한 대화를 다시 불러오지만 다른 Codex 프로세스에서 동시에 일어난 변경이 화면에 실시간으로 스트리밍된다고 보장하지 않습니다. 대화를 이어가려면 여전히 **Codex로 실행**을 명시적으로 선택해야 합니다.

원본 실행 기록과 증거는 기본적으로 접혀 있습니다. 일반 명령의 종료 코드는 관찰한 사실이며 구현의 정확성을 검증한 근거로 승격하지 않습니다. 재시도와 복구는 예전 로그에서도 해당 로그의 정확한 Run을 대상으로 하며 Codex를 다시 실행하지 않습니다.

실행 요약은 해당 Run의 저장된 최종 보고서와 관련 실행 증거를 보통 2–3개의 짧은 문장으로 정리합니다. 중요한 실패·차단·미완료 사항은 길이 제한으로 숨기지 않습니다. 보고된 주장과 초안은 발송·실제 완료·독립 검증으로 승격하지 않습니다. 예전 빈 정리나 생성 실패는 원본 기록 확인과 명시적 재시도로 안내하며, 보고서 누락·생성 중·실행 실패를 구분합니다. 원문을 잘라 요약으로 대신하지 않습니다.

Work Log는 **요청 → Codex가 수행한 작업 → 결과** 순서로 표시합니다. 요청에는 같은 세션의 후속 실행을 포함하여 해당 Run에 저장된 원래 instruction을 사용합니다. 과거 항목에 요청이 없으면 확인할 수 없다고 표시하며 현재 Task 설명을 대신 사용하지 않습니다. 기본 보기에는 저장된 요약 최대 세 항목과 모든 미해결·상충 항목, 실패와 제한 사항을 표시합니다. 최종 보고서만 출처인 주장은 Codex 보고로 표시하고 초안이라는 표현을 유지합니다. 요약 상세·주장 상태·정확한 출처와 원본 실행 기록은 기본적으로 접혀 있으며 펼쳐서 해당 세션과 Run을 확인할 수 있습니다. 과거 데이터는 변경하지 않습니다.

## 보류와 실행 대기

Workbench 카드와 제목은 Task가 있으면 상세를, Capture와 이전 Problem 항목은 해당 다듬기를 엽니다. 별도 **다듬기** 버튼은 그대로 사용할 수 있습니다. 카드 배경 클릭은 내부 버튼·링크·하위 카드·접기 제어와 텍스트 선택을 방해하지 않습니다.

기존 삭제 위치의 **⋯** 메뉴는 진행 중 Task에 **보류 / 실행 대기로 이동 / 삭제**, 보류 Task에 **재개 / 실행 대기로 이동 / 삭제**를 제공합니다. 다른 상태와 Capture·이전 Problem 항목에는 삭제만 있습니다. 삭제는 구분된 마지막 항목이며 기존 확인 절차를 거칩니다. 키보드로 메뉴를 열고 화살표·Home·End로 이동할 수 있으며 Escape는 메뉴를 닫고 버튼에 포커스를 돌립니다.

**보류**는 진행 영역 가까운 공용 **보류(n)** 접이식 영역으로 옮기며, 정제 상태를 되돌리지 않습니다. **재개**는 같은 Task와 세션을 진행 중으로 돌립니다. **실행 대기로 이동**은 정제된 Task 레인에 놓지만 readiness를 충족했다고 표시하지 않습니다. 열린 정제 세션은 보존하고 명시적인 실행 대기 배치가 레인 선택에 우선합니다. 하위 Task도 실행 대기 이동 시 해당 레인에 직접 표시되며 부모 관계는 유지됩니다. 다시 시작하면 이 배치 우선권을 해제합니다.

어느 동작도 Task 내용·정제 revision·작업 기록·세션·최초 시작 시각을 삭제하지 않습니다. 상태 전이는 별도 이력으로 저장하고 상세의 **상태 이력**에서 확인합니다. 완료 후 다시 열기는 기존 명시적 reopen 동작으로 유지됩니다.

Task 안의 어떤 세션이든 에이전트 실행이 대기·실행·응답 대기 중이면 보류와 실행 대기 이동을 서버에서 거절합니다. 전송 결과가 불확실한 실행도 먼저 확인해야 합니다. 현재 이 메뉴에는 불확실한 실행의 종료를 확정하거나 차단을 해제하는 조작이 없습니다. 에이전트를 완료하거나 명시적으로 중단하고 종료를 확인한 뒤 다시 시도하세요. Task 보류는 에이전트를 자동으로 취소하지 않습니다. 보류 중 새 실행도 서버에서 거절하며 먼저 Task를 재개해야 합니다.

접힌 보류 영역은 항목이 없어도 제목과 개수만 표시합니다. 펼치면 고정 폭 카드가 한 줄로 나열되며 좌우 스크롤과 키보드 포커스를 지원합니다. 세로 레인으로 줄바꿈되거나 카테고리 보드 뒤로 늘어나지 않습니다.

## 완료된 Task와 새 메모

Task를 완료하면 작업 정의, 체크리스트, 기존 작업 로그와 저장된 실행 이력이 읽기 전용으로 유지됩니다. 완료된 Task의 기존 세션 설정은 편집할 수 없으며 새 Codex 실행도 시작할 수 없습니다. 뒤늦게 도착한 실행 결과, 이미지 요약과 작업 로그 요약은 완료된 근거를 덮어쓰지 않습니다. 실행 중이거나 결과가 불확실한 실행은 종료 또는 중지 후 종료를 확인해야 Task를 완료할 수 있습니다. 마지막 하위 Task의 완료가 부모 Task를 완료시키는 경우에도 같은 규칙을 적용합니다. 실행의 최종 상태와 최종 보고서는 함께 저장됩니다.

사용자는 첨부 파일을 포함한 새 메모를 **메모 저장**으로 추가할 수 있습니다. 완료된 Task에서는 Enter를 누르면 메모를 저장하며 Codex를 실행하지 않습니다. 기존 세션 항목 경로에 새 항목을 덧붙이며, 이전 항목·Task 상태·작업 로그를 바꾸지 않습니다. 기존 세션이 없다면 새 세션에 메모를 남길 수 있습니다. 완료 시점 이후의 메모는 **완료 후 메모**로 표시합니다. 저장된 실행 이력은 계속 읽을 수 있고, 별도 Knowledge 편집·검토·발행 흐름도 유지됩니다.

## 실행 환경과 후속 대기 요청

세션 표시 라벨은 처음 저장한 사용자 요청·메모를 사용하고, 없으면 기존 대화 라벨을 사용합니다. 라벨을 직접 편집하지 않으며 과거 저장 제목은 보존합니다. 세션 목록은 하나의 레일로 유지하고 Task 맥락·실행 기록·실행 환경은 펼쳐 확인합니다. 완료된 Task에서는 완료 후 메모를 선택적으로 펼치며 실행 버튼은 표시하지 않습니다.

실행 환경의 프로젝트 폴더·모델·승인 검토자는 같은 세션에서 재사용합니다. **추론 레벨**은 **기본값 상속 · Codex 설정 사용**과 선택한 모델이 보고한 지원값만 제공합니다. **지원 모델 새로 확인**은 로컬 Codex의 모델 지원 정보를 읽습니다. 모델 변경 후 미지원 레벨은 경고와 함께 상속으로 전환되며 저장 후 다시 준비해야 합니다. 지원 정보·설정값을 확인하지 못하면 기존 수동 실행의 상속 선택은 유지하지만, 새 대기 요청을 추가하려면 실제 추론값 확인이 필요합니다. 이 설정은 AI 설정의 별도 endpoint·모델 라우팅을 변경하지 않습니다. 연결된 대화의 폴더는 읽기 전용이므로 다른 폴더는 새 세션을 사용하세요. 실행 중이거나 완료된 Task에서는 세션 설정을 편집할 수 없습니다. 변경값을 저장한 뒤 대화를 준비하며, 준비만으로 작업이 시작되지 않습니다.

실행 중에도 같은 입력창으로 후속 작업을 작성하고 **대기 요청에 추가**를 선택할 수 있습니다. Enter도 대기 요청을 추가하며 Shift+Enter·IME 조합 확정 동작은 기존대로 유지합니다. 대기 요청은 현재 실행에 끼어들지 않으며 **메모 저장**은 별도입니다. 각 요청에 순서·프로젝트·모델·확정 추론값을 표시하고 편집·삭제·위아래 순서 변경은 저장 revision을 확인합니다. 추가 시점의 설정과 승인·설정 revision을 기록하므로 나중에 기본값을 바꿔도 기존 대기 요청이 조용히 변경되지 않습니다. 설정이나 승인 revision이 바뀌면 목록을 멈추며, 환경을 검토·준비한 뒤 해당 요청을 삭제하고 명시적으로 다시 추가하세요.

현재 실행의 성공 종료가 확인되면 기존 실행 서비스를 통해 대기 요청을 하나씩 진행합니다. 대기 목록에 추가한 것만으로 Work Log를 만들지 않으며 실제 전송 시 해당 요청의 변경 불가능한 Run·요청·최종 보고·Work Log 출처 연결을 저장합니다. 직렬화 범위는 세션 단위이며 다른 세션까지 프로젝트 전체를 잠그지는 않습니다.

**현재 작업 중단 후 대기 요청 실행**은 정확한 현재 Run에 중지를 요청하고 제공자의 종료 확인을 받은 뒤 목록을 실행합니다. 중지 요청 접수만으로는 다음 실행을 시작하지 않습니다. **대기 실행 취소**는 이후 실행 의도를 취소하고 목록을 멈추지만, 이미 전달된 중지를 철회하거나 수행한 작업을 되돌릴 수는 없습니다. 일반 **중지**는 후속 자동 실행을 멈춥니다. 승인·질문 응답 대기는 같은 실행을 유지하고 실패·취소·결과 불확실 상태에서는 검토를 위해 대기 목록을 멈춥니다. 불확실한 요청은 자동 재전송하지 않습니다. 명시적인 대기 실행 계속은 실패한 Run의 재시도가 아니라 남아 있는 지시의 실행입니다.

대기 요청은 native 저장소에 보존되어 Task를 닫아도 유지됩니다. 입력 중인 초안·답변·첨부·대기 요청 편집 초안은 기존 Task/세션 메모리 저장소로 유지하므로 앱 재시작 후 복원을 보장하지 않습니다. 기존 세션을 업그레이드하면 한 번 대화를 다시 준비해 실행 설정을 확인해야 합니다. 재시작 시 자동 Queue는 재검토 필요 상태로 복구하고 제공자 결과의 불확실성을 보존합니다. Task를 완료하거나 보류하려면 남은 대기 요청을 먼저 취소해야 합니다. 완료 Task는 대기 요청 추가·설정 편집·실행을 허용하지 않지만 덧붙이는 메모와 별도 Knowledge 작업은 유지합니다. Queue는 Task 완료나 Knowledge 발행을 대신하지 않습니다.

대화 준비를 반복하면 같은 연결 세대와 저장된 설정에서 확인한 실행 중 대화를 유지하면서 모델·추론 정보를 확인합니다. 설정 확인만을 위해 디스크의 대화를 다시 불러오지 않습니다. 제공자 재시작 후 대화를 찾지 못하면 오류를 표시하고 기존 세션과 기록을 보존합니다. 원래 Codex 연결에서 재시도하거나 사용자가 명시적으로 별도 새 세션을 만들 수 있습니다.

준비되지 않은 세션은 대화 기록 앞에서 실행 환경 설정을 펼칩니다. 새 세션·연결은 세션 탐색 영역에 있고, 실행 중에는 추가 작업 요청을 입력할 수 있습니다. 현재 승인·입력 요청은 기록보다 먼저 표시합니다. 저장 전 환경 변경을 취소하면 저장된 설정으로 돌아가며 요청 초안은 유지합니다. 완료된 기록에서는 새 세션·연결을 표시하지 않고 별도 메모 추가를 접어 둡니다.

열린 Task 상세 화면은 세션 snapshot의 저장된 Run 또는 동기화 revision이 바뀌면 Work Log를 다시 읽습니다. 실시간 텍스트 조각마다 Task를 조회하지 않습니다. 겹치는 갱신·로그 열기 조회는 합치며, 조회 중 저장 변경이 추가되면 후속 조회로 반영합니다. Work 탭이나 특정 Work Log 링크를 열 때도 저장 상태를 다시 읽고 작성 중 초안은 유지합니다. Work 탭은 실제 실행·실행 가능한 Queue·정리 job이 진행 중인 동안 갱신하며, 실행이 끝나거나 Queue가 일시정지되면 멈춥니다. 기존 이미지 요약·번역 갱신 동작은 유지합니다. 저장된 실행·Queue 의미를 바꾸지 않는 표시 갱신 수정입니다.

## 최초 Task 및 작업로그 맥락

세션의 최초 실제 작업 요청에는 최신 Task 정의와 해당 Task에 저장된 모든 작업로그 본문, 댓글, 연결된 Run의 요청 원문과 저장된 최종 보고서를 포함합니다. 대화 준비는 설정만 확인하며 맥락 전달 완료로 기록하지 않습니다. 출처 ID, 기록 시각, Run 상태를 구분하고 Codex가 작성한 보고서를 독립 검증으로 취급하지 않습니다. 현재 요청의 Run과 작업로그가 생성되기 전에 수집하므로 자기 요청은 포함하지 않습니다.

AI 설정의 **Context Size**는 추가로 전달할 저장된 맥락의 크기입니다. 새 설정과 기존 설정 모두 기본값은 **64 KiB(UTF-8 65,536바이트)**입니다. 1–32,768 KiB의 정수로 수정할 수 있고 재시작 후에도 유지됩니다. 저장한 값은 새 맥락 준비부터 적용하며 진행 중인 요약에는 적용하지 않습니다. 토큰 64K나 모델 전체 한도, 대화의 남은 용량을 뜻하지 않습니다. 현재 사용자 요청을 이 크기에서 빼거나 요약·절단하지 않으며 기존 100,000바이트 검증도 유지합니다. 큰 설정값은 실제 제공자 한도를 넘을 수 있고 이때는 제공자 오류를 표시합니다.

설치된 Codex schema의 model/list에는 입력 용량 필드가 없습니다. config/read의 model_context_window는 선택적 설정값이며 모든 모델의 실제 capability나 대화의 남은 용량을 뜻하지 않습니다. 이 값으로 사용자 요청 수락 여부를 추정하지 않습니다.

Context Size 초과 시 기존 AI 설정의 Run 보고서 요약용 텍스트 provider·모델로 모든 원문 구간을 의미 요약하고 다단으로 축약합니다. 세션 Codex 모델과 다를 수 있고 기존 AI 설정이 필요하지만 공급자나 자격증명을 추가하지 않습니다. 모든 원문 바이트와 경계의 인접 문맥을 전달하며 결론·조건·예외·정정과 철회·시각·기록된 작성자·상충 내용·불확실성을 보존하도록 지시합니다. 별도 출처 목록으로 ID와 시각을 유지하며 작성자를 추정하지 않습니다. 중간 정정을 빠뜨릴 수 있었던 기존 키워드 발췌를 대체합니다.

알려진 한도는 공식 OpenAI endpoint의 정확한 gpt-4.1(1,047,576토큰), gpt-4o(128,000토큰)에만 적용합니다. 2026-10-23 확인한 [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1), [GPT-4o](https://developers.openai.com/api/docs/models/gpt-4o) 문서 기준입니다. 프록시·별칭·다른 모델은 모델 전체 한도를 추정하지 않고 명시적인 Context Size을 사용합니다. 입력 청크는 JSON 이스케이프와 출처를 포함해 최대 16 KiB, 생성 요약은 UTF-8 2,400바이트와 요청 출력 2,400토큰으로 제한하고 최종 전달에는 설정한 Context Size도 적용합니다. 알려진 요약 모델에는 시스템·프로토콜과 출력·추론 여유를 확보하며 현재 사용자 요청은 요약 호출에 포함하지 않습니다. provider 수락을 보장하지 않습니다.

Task 작업 시작 전 비용·지연 안내와 맥락 준비 취소를 표시합니다. 추가 호출로 비용이 발생할 수 있습니다. 취소는 로컬 HTTP 대기를 중단하지만 원격 연산·과금 중단까지 보장하지 않습니다. 실패·취소·거절·잘리거나 잘못된 응답·출력 초과·축약 실패·출처 초과·처리 제한에서는 실행하지 않고 Queue 요청을 삭제하지 않은 채 일시정지합니다. 원문 32 MiB, 호출 256회, 축약 10단계 제한은 부분 성공이 아닌 명시적 실패입니다. Run 생성 전 실패·취소 후 재시도는 비용을 반복할 수 있으며 Run 생성 이후 같은 작업 ID 재호출은 요약·실행을 반복하지 않습니다. 요약의 영구 체크포인트·재개는 제공하지 않습니다.

사용자와 AI 양쪽에 원문 전체 대신 모델 요약을 전달했음을 알립니다. Run에 요약 모델·호출 수, 출처 수, 수집 시각, 바이트, Context Size 근거와 전달 상태를 기록합니다. 전체 입력을 처리해도 의미 보존을 보장하지 않으며 모델이 조건을 잃거나 틀릴 수 있습니다. 합성 fixture 검증을 실제 모델 품질 검증으로 표현하지 않습니다.

실제 최초 전달 내용은 Run에 고정합니다. 전달 표시는 수집한 Task 정의의 해시를 사용합니다. 모델 요약 중 Task가 바뀌면 그 변경을 전달 완료로 표시하지 않고 다음 요청의 기존 기본 필드 변경 전달 대상으로 유지합니다. provider가 턴 시작을 수락해야 전달 수락으로 기록하며, 준비·대기·불확실한 오류는 전달이나 AI의 열람을 증명하지 않습니다. 같은 작업 ID를 재호출해도 요청을 중복 전송하지 않습니다. 수락 이후에는 기존 Task 기본 필드 변경 전달 동작을 유지하며 새 작업로그를 자동 보충하지 않습니다. 기존 세션도 업그레이드 후 다음 실제 요청에 최초 스냅샷을 받습니다. 데이터베이스 버전 27은 기존 로그와 결과를 바꾸지 않고 nullable Run 전달 내용 열만 추가합니다.

저장된 텍스트만 대상으로 하며 바이너리 첨부, 이미지 픽셀, 임의 파일은 포함하지 않습니다. 과거 저장 시 이미 제한되거나 가려진 보고서에서 저장되지 않은 provider 원문을 복원하지 않습니다. MCP 도구나 범용 Task 조회 기능은 추가하지 않습니다. 합성 데이터로 전송·저장·UI 계약을 검증했으며 실제 provider 실행과 데스크톱 화면 검증은 미완료입니다.

실행 전 요약도 AI Queue에서 직접 요청으로 추적하며 실제 모델과 API 호출 시작·완료 횟수를 표시합니다. 실제 작업은 선택한 Codex 모델이 수행합니다. 큐 취소는 원래 요약 요청에 연결되지만 이미 시작된 호출의 과금을 취소한다고 보장하지 않습니다. 원래 화면 열기는 해당 Task·세션으로 이동합니다. 큐 재시도는 제공하지 않으며 결과를 확인한 뒤 원래 화면에서 새 요청을 명시적으로 보냅니다. 재시작 시 미완료 추적 기록은 실패로 표시하고 자동으로 다시 실행하지 않습니다. 기존 세션의 메모리 내 미전송 입력 보존이 재시작 후 보존으로 바뀌는 것은 아닙니다.

## 실행 중인 작업이 있는 Task 완료

기존 Task 완료 버튼과 완료 근거 입력을 그대로 사용합니다. 실행이나 대기
요청이 완료를 막으면 **중단하고 완료**가 영향을 주는 실행, 대기 지시, 응답
대기 목록을 보여 줍니다. 확인 전에 취소하면 아무것도 바꾸지 않습니다. 확인하면
Task의 모든 세션 큐를 일시 정지하고 검토한 대기 항목을 취소하며, 종료를 확인하는
동안 새 실행을 막습니다. 기존 결과와 작업로그는 보존합니다.

중단 요청의 응답만으로 Task를 완료하지 않습니다. 저장된 제공자 대화와 정확한
실행을 확인하며, 실제 종료가 확인되고 로컬 상태만 남은 경우에는 해당 결과를
복구합니다. 모든 실행이 끝난 뒤에만 완료합니다. 실행 식별자가 없거나 제공자에
접근할 수 없거나 결과가 불확실하면 이유와 함께 대기 상태를 유지하고 다시 확인할
수 있습니다. 불확실한 실행을 임의로 완료 상태로 덮어쓰지 않습니다. 새 실행이 시작되거나 대기 지시가
수정되면 목록을 다시 검토하며, 같은 실행의 일반적인 스트리밍 갱신은 확인을
무효화하지 않습니다. 중단을 시작한 뒤에는 대기 중인 제공자 응답을 승인할 수
없습니다. Task 정의가 바뀌면 기존 리비전 검사를 적용합니다.

응답이 지연되는 동안에도 **완료 취소**를 사용할 수 있습니다. Task는 진행 중으로
남고 늦게 도착한 응답이 Task를 완료하지 못합니다. 이미 보낸 중단 요청과 취소한
대기 항목은 되돌리지 않으며, 큐는 사용자의 명시적인 결정을 위해 일시 정지
상태로 유지합니다. 완료 화면에 다시 들어오면 이미 승인된 대기 요청을 이어서
확인하며 중복 요청을 만들지 않습니다. Task 완료와 Knowledge 발행은 별개입니다.
