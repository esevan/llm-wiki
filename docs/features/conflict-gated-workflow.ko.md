# Task 중심 Workbench

[English](conflict-gated-workflow.md) | **한국어**


Workbench는 진행 중인 모든 Task를 Capture 위에 표시합니다. **진행 중인 작업에 Focus**로 다른 영역을 숨길 수 있습니다. 정제 결과는 **Refined - Revision N**으로 표시하며, 정제 적용과 실행 상태를 구분합니다. 명시적인 Subtask는 부모 아래에 들여쓰기와 펼치기로 표시합니다. 경계 맥락과 부모 자동 완료·Knowledge 발행은 [Refinement와 Subtask](refinement-preview-status.ko.md)를 참고하세요.

## Capture와 작업 정제

생각·문제·이미 찾은 해결책을 Capture에 기록하며, 정해진 단계를 반드시 거칠 필요는 없습니다.
Workbench의 간결한 두 줄 입력에서는 텍스트 아래에서 Capture와 Task를 선택하고 저장하며, 사용할 수
있는 폭이 좁으면 이 행은 자연스럽게 줄바꿈합니다.
단순한 업무는 바로 **Task**로 만들 수 있습니다. 맥락이나 검토 가능한 제안이 더 필요할 때
[Refinement](refinement-preview-status.ko.md)를 사용하고, Capture에 이미 기록한 해결책은 보존합니다.
Workbench 입력에서 **Enter**를 누르면 저장하고, 줄바꿈은 **Shift+Enter**를 사용합니다. IME 조합
중에는 Enter가 조합을 완료할 수 있도록 제출하지 않습니다.

하나의 Capture에서 여러 Problem과 Task가 나올 수 있습니다. Problem은 변경 이력을 리비전으로
보존하며, Task는 해결하려는 정확한 리비전에 연결됩니다. 다른 Task를 선행 작업이나 관련 작업으로
연결할 수도 있습니다. 이 연결은 작업 흐름을 보존하지만 1:1 관계를 강제하지 않습니다.
관련 작업은 양쪽 Task에서 조회하고 연결을 해제할 수 있으며, 선행 작업 연결은 방향을 유지합니다.

## 보드에서 이어가기

Workbench는 진행 중인 모든 Task를 맨 위에 보여주고, 가벼운 입력 영역 아래에 세로 레인 세 개를 배치합니다.
**Inbox**에는 Task로 전환되지 않았고 진행 중인 다듬기 세션이 없는 Capture, **다듬는 중**에는 저장된 다듬기 항목과 기존
Problem 전용 항목, **정제된 Task**에는 진행 중인 다듬기 세션이 없는 등록된 Task가 나타납니다.
각 항목은 한 번만 표시하며, 진행 중인 Task는 다듬기 세션이 있어도 상단에 유지합니다.
완료한 Task는 오른쪽 레인의 접힌 영역에서 펼쳐 볼 수 있습니다. 분류명은 카드에 남습니다.
저장된 다듬기는 바로가기 개수 제한 없이 모두 표시합니다. 좁은 창에서는 같은 순서로 레인을
세로로 쌓습니다. 각 카드에서 열기, 다듬기, 삭제를 계속 사용할 수 있습니다.

Task와 진행 중인 Task는 구분됩니다. 사용자가 작업을 시작하고 근거와 함께 완료하며, 완료한 Task를
다시 열 수도 있습니다. 정제 준비 상태는 어떤 준비 항목이 채워졌고 무엇이 더 필요한지 보여 줍니다.
적용되지 않는 항목에는 이유를 남길 수 있습니다. 이 정보는 작업 재개를 돕고 별도의 필수 승인 단계가
되지는 않습니다.

## 작업 기록 유지하기

Task를 열면 Workbench 위에 집중 모달로 상세가 열립니다. 대화상자가 열려 있는 동안 배경은 조작할 수
없으며, `Escape` 또는 **Task 상세 닫기**를 사용하면 가능한 경우 열었던 항목으로 포커스가 돌아갑니다.
포커스가 밖으로 빠져도 Escape는 최상위 대화상자에만 적용되며 로딩·불러오기 오류 화면도
포함합니다. 미저장 변경 확인과 변경 처리 중 닫기 제한은 유지됩니다.
상세의 **작업**, **세부 정보**, **검토** 탭에서 체크리스트·Work Log·결정, 읽기 중심 정의와 명시적
편집, 준비 상태·충돌 검토·완료·Knowledge를 각각 확인합니다. 대화상자는 자체 스크롤을 사용하며 좁은
창에서는 사용 가능한 높이에 맞춥니다. Workbench가 열려 있는 동안 Task별 초안과 선택한 탭을 유지합니다.
진행 중인 Task는 처음에 작업 탭, 시작 전 Task는 세부 정보 탭, 완료한 Task는 검토 탭으로 열립니다.
다시 열면 마지막 탭을 복원합니다. 체크리스트는 처음에 미완료 항목 다섯 개까지 보여주며, 목록을
펼치면 완료 항목을 포함한 전체 항목을 확인합니다.

Task 상세에서는 제목·상세·결과·범위·제외 범위·검증 기준의 여섯 정의 필드를 Work Log·첨부·댓글·
체크리스트·결정과 함께 기록합니다. 편집 내용은 **변경 저장**을 누르기 전까지 로컬에 남습니다.
Work Log 입력에서 **Enter**를 누르면 기록을 추가하고, 줄바꿈은 **Shift+Enter**를 사용합니다.
체크리스트 항목과 Work Log 댓글도 **Enter**로 추가합니다. 빈 입력이나 한글 등 IME 조합 중 누르는 Enter는 저장하지 않습니다.
Work Log 입력에 스크린샷을 붙여 넣으면 바로 첨부할 수 있습니다. 텍스트 없이 이미지 파일만
있는 항목도 기록할 수 있으며, 일반 텍스트 붙여 넣기는 평소처럼 입력됩니다. 선택한 첨부 파일
이름은 항목을 추가하거나 다른 파일로 바꿀 때까지 표시됩니다.
저장한 이미지 첨부는 기존 기록에서 가져온 이미지를 포함해 해당 Work Log 항목 안에 표시됩니다. 다른 첨부 파일은 파일 이름으로 표시됩니다. 이미지를 저장하면 한글·영문 AI 요약도 큐에 제출합니다. 기존 이미지에서도 요약을 요청할 수 있으며, 완료된 요약은 화면 언어에 맞춰 표시됩니다.
Work Log 항목은 최신 항목부터 표시하며, 각 기록에 사용자의 현지 날짜와 시간을 함께 표시합니다.
별도로 저장한 변경이나 새로 고침이 있어도 저장하지 않은 정의 초안을 덮어쓰지 않습니다. 저장할 때
초안을 시작한 Task 리비전을 함께 보내며, 같은 필드가 다른 곳에서 바뀌었으면 최신 기록과 내 초안을
비교해 의도적으로 내 편집을 유지하거나 최신 값을 사용합니다. 저장에 실패해도 입력과 오류를 남겨
다시 시도할 수 있습니다.

정의 초안이 남은 Task 상세를 닫거나 다른 Task를 선택하면 **저장**, **버리기**, **계속 편집**을
선택합니다. shell은 route가 숨겨져도 열린 상세를 유지하므로 일반 탐색으로 초안을 버리지 않습니다.
이는 Task 정의 필드의 명시적 저장 보호이며 Task 자동 저장이 아닙니다. 앱 종료·충돌 때의 내구성이나
모든 보조 입력 양식을 보장하지 않습니다.

**완료 근거 추가**로 완료를 시작합니다. Task를 완료해도 연결된 Problem이나 다른 Task가 자동으로 해결·완료되지는 않습니다. Problem은
현재 리비전과 근거를 기준으로 별도 해결합니다. 과거에 연결한 리비전을 현재 리비전처럼 해결할 수는
없습니다. 비공개 Knowledge 초안 생성과 발행도 각각 명시적인 결정입니다.
[완료와 Knowledge 안내](completion-writeback-archive.ko.md)를 참고하세요.

## 작업을 막지 않는 충돌 검토

충돌 검토는 비동기로 실행하며 시도와 근거를 보존합니다. 검토 동작에서 취소하거나 재시도할 수
있습니다. 관련 Task·Capture, Vault 근거, 검토 범위가 바뀌면 결과는 오래된 것으로 표시됩니다.
실패나 부족한 근거를 충돌 없음으로 간주하지 않으며, 충돌이 Task를 자동 승인하거나 차단하지 않습니다.

Queue에서는 이전 흐름에서 보존한 보고서도 열 수 있습니다. 이 화면에 표시된 충돌 결정 동작은
사용자의 결정과 메모를 저장하며, 폐기된 Problem 승인 흐름을 다시 요구하지 않습니다.

## 작업대 항목 삭제

각 Capture, Task, 마이그레이션된 Problem 카드에는 삭제 동작이 있습니다. Task 상세에서도 삭제할 수 있습니다. 확인창에는 항목 제목을 표시하며, ‘항목 유지’나 Escape로 취소할 수 있습니다. 저장하지 않은 Task 변경이 있으면 먼저 저장·폐기·계속 편집 중 하나를 선택합니다. 확인한 삭제는 원본 기록을 보존하고 작업대에서 숨깁니다. 취소하면 카드가 그대로 남고, 요청이 실패하면 오류를 확인 대화상자에 남겨 다시 시도할 수 있습니다. 확인한 항목은 새로 고침 뒤 숨겨지며, 연결된 Knowledge 기록과 보관함 파일은 유지됩니다. 진행 중인 다듬기 결과도 삭제한 항목을 다시 보이게 하지 않습니다.

관련 Spec Kit: [012 — Task 중심 Workbench](../../specs/012-task-centered-workbench/spec.md).
이전 계약: [002 — Conflict-Gated Workflow](../../specs/002-conflict-gated-workflow/spec.md).

다듬기도 작업대 위에 뜨는 창 대신 작업 영역을 차지합니다. Capture는 작업대와 다듬기를 절반씩 표시하고, Task는 기존 세부 정보를 왼쪽에 유지하고 다듬기를 오른쪽에 표시합니다. 저장 전 Task 입력과 선택한 탭을 보존하며, 좁은 창에서는 돌아가기 동작이 있는 다듬기 화면으로 전환합니다. 대화와 문서형 제안 결과 프리뷰를 함께 보여주고, 별도 저장 메모는 접어서 제공합니다. 제안은 명시적으로 적용하기 전까지 원래 작업을 바꾸지 않으며, 편집은 해당 필드를 정확히 수정합니다. Task 제안을 적용하면 유지 중인 세부 정보도 갱신됩니다. 작업대에서 여는 이전 Problem 다듬기도 기존 프리뷰와 API를 유지하면서 분할 영역에 표시합니다.
