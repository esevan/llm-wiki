# 검토 후 지식 아카이빙

Workbench와 Compass의 완료된 Task 목록 모두에서 발행 검토를 열 수 있습니다. 검토 준비는 로컬 보관함에 저장할 정확한 파일을 제안하며, 발행하려면 사용자가 별도로 승인해야 합니다. 외부 저장소 연결은 필요하지 않습니다.

지식을 게시하기 전에 정리 제안을 검토합니다. 실제 저장할 마크다운·YAML,
정규 경로, 태그·별칭, 별도로 선택한 아이디어 문서, 출처 링크와 MOC 변경을
보여줍니다. 제안을 생성하는 동안 파일은 바뀌지 않습니다. 게시하면 검토한
바이트를 그대로 저장하며, 출처나 대상이 달라졌거나 충돌하면 다시 검토합니다.
기존 분류를 우선하며 새 분류에는 이유가 필요합니다.

최종 결정은 Knowledge에 남깁니다. 보류·기각·미검증·범위 밖 아이디어는
다시 고려할 조건과 함께 별도 `idea/` 문서로 저장합니다. 출처에는 실제
참조한 버전·섹션·사용 이유가 남습니다. 검색하거나 열어본 것만으로 게시
출처가 되지는 않습니다.

파일 저장 후 인덱스 반영 중에는 이전 게시 포인터를 유지합니다. 정확히 같은
파일이 인덱싱되어야 게시가 완료됩니다. 인덱스 재시도는 문서를 다시 생성하지
않습니다. 복구 자료를 보관하며 재시작 시 모델 호출 없이 기록된 작업을
이어갈 수 있습니다. 외부 수정은 보존하고 필요한 경우 복구 검토를 요청합니다.
되돌리기는 해당 작업이 만든 뒤 변경되지 않은 바이트만 복원합니다.

이동·이름 변경·철회·복구 제안도 검토 후 적용합니다. 문서 정체성과 이력을
유지하고 관리 영역의 링크를 고칩니다. 사용자가 작성한 일반 링크는 임의로
고치지 않고 알립니다. 결정 대체는 같은 주제에만 적용하며 다른 주제의 최종
결정은 유지합니다. 마크다운과 YAML은 앱 없이도 읽을 수 있습니다. 개인
외부 Obsidian Vault 연결은 이번 기능에 포함하지 않습니다.

검토 화면을 다시 열면 저장된 작업 상태를 표시합니다. 색인 재시도는 같은 발행 작업을 `index_pending`으로 전환하며, 큐 등록에 실패하면 `index_failed`로 남습니다. 파일 복구가 필요한 작업은 먼저 복구 방법을 선택해 해결해야 합니다.

호환 발행 명령도 같은 아카이브 색인 수명주기를 사용합니다. 복구가 필요하거나 완료된 작업을 다시 요청해도 예전 번역 작업이나 중복 전체 색인 작업을 시작하지 않습니다.


검토 화면은 핵심 내용과 추후 활용을 펼쳐 보여줍니다. 출처, 아이디어, 버전 및 초안 도구는
접어서 유지합니다. Task 검토 탭의 별도 충돌 검토 패널은 제거하며 과거 기록은 보존합니다.
의견은 정확한 버전에 연결되는 비공개 기록으로만 저장되며 본문을 자동 수정하거나 주장을
검증하지 않습니다.

**Knowledge 발행**을 누르면 준비된 저장 경로를 확인하고 명시적으로 발행을 승인합니다.
발행 취소는 파일을 쓰지 않고 확인 화면을 닫습니다. 기존 파일의 예상하지 못한 변경은
계속 발행을 차단합니다. 이 파일 보호는 제거한 충돌 검토 UI와 별개입니다. 근거 스냅샷이
없는 이전 초안은 계속 읽을 수 있으며, 발행하려면 새 초안을 생성해야 합니다.

검토 탭은 준비 상태·품질 검증 패널 없이 본문, 추후 활용, 출처와 비공개 의견을 보여줍니다.
발행 동작 시 실제 근거 불일치나 파일 보호 문제를 쉬운 문장으로 알리고 바로 재생성할 수 있습니다.
내부 검증 JSON·출처 ID는 품질 메시지로 노출하지 않습니다. 생성 중 잘못된 인용이나 근거 없는
확정 주장은 동일한 원본 스냅샷으로 한 번만 자동 재시도하며, 다시 실패하면 계속 차단합니다.
불완전한 이전/수동 문서는 추가 모델 호출 없이 보존합니다. 사용자에게 별도의 수동 검증을
요구하지 않으며 의견은 주장의 검증을 대신하지 않습니다.

검토 화면의 큰 읽기 영역에는 본문·최종 결과·추후 활용을 표시합니다. 오른쪽 보조 열에는 비공개 의견, 편집과 버전 선택, 명시적 발행 동작을 배치합니다. 좁은 창에서는 컨트롤이 본문 뒤에 이어집니다. 출처 확인은 접힌 영역에 보존해 읽기 흐름을 유지합니다.
