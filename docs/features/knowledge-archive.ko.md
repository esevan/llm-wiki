# Knowledge 발행과 아카이브

[English](knowledge-archive.md) | **한국어**

Task 검토 탭에서 **Knowledge 발행**을 한 번 누르면 내용이 있는 선택 초안을
발행합니다. AI 구성 요청이나 두 번째 승인 화면은 없습니다. 편집 중인 본문은
새 버전으로 먼저 저장합니다. 발행 버튼 자체가 명시적인 발행 결정이며,
채팅 제안을 생성하거나 적용하는 것만으로는 발행하지 않습니다.

품질 확인 사항, 인용 불일치, 출처 최신성, 활용 해석, 근거 부족은 일반 발행을
차단하지 않습니다. 실패한 기존 초안과 생성 스냅샷 없는 이전 초안도 재생성 없이
발행할 수 있습니다. 사용자의 경험과 직접 작성한 설명은 그 자체로 출처입니다.
외부 인용은 선택 사항이며 인용이 없다는 이유만으로 품질 실패로 처리하지 않습니다.

일반 발행은 안정적인 문서 정체성과 버전 이력을 유지합니다. 관련 없는 기존 파일과
서로 다른 주장을 모두 보존합니다. 발행이 AI 내용을 검증된 사실이나 사용자 본인의
직접 경험으로 바꾸지는 않습니다. 출처 연결, 사용자 진술, AI의 주장·추론 연결과
확인 사항은 메타데이터로 남습니다. 발행 문서는 내용 검색에 노출되며 검증 여부는
별도로 유지합니다. 검색은 원본 리비전, 조건, 출처 구분과 비교 대상 목록을 반환해
맥락을 비교하도록 합니다. 의미적 충돌을 자동 판정하거나 파괴적으로 병합하지 않습니다.

저장 무결성 문제는 계속 보호합니다. 선택 버전 변경, 예상하지 못한 파일 수정,
이미 사용 중인 목적지, 안전하지 않은 경로와 디스크 오류에서는 발행 포인터를
임의로 바꾸지 않습니다. 반복 클릭은 같은 입력에 연결된 작업을 재사용합니다.
`index_pending`은 정확한 파일 저장 후 색인을 기다리는 상태이며 실제 색인 작업이
같은 바이트를 확인해야 발행 포인터가 바뀝니다. 재진입하면 저장된 상태를 복원합니다.
색인 재시도는 내용을 재생성하지 않으며 복구·보상은 외부 수정 파일을 보존합니다.

이동·이름 변경·철회·복구는 기존 구성을 바꾸므로 정확한 파일을 별도로 검토합니다.
기존 고급 구성 제안은 호환 유지합니다. 아이디어는 선택적으로 별도 문서에 저장하며
미검증·보류·범위 밖·기각 상태와 다시 검토할 조건을 유지합니다.

### 읽을 수 있는 제목과 주제별 목차
발행 제목은 저장된 글 제목을 사용합니다. 기계 식별자 형태라면 의미 있는 H1,
Task 제목 순서로 대체합니다. 검색과 재색인은 frontmatter 제목, H1, 파일명
순서로 표시 제목을 결정하며 내부 문서 ID는 유지합니다.

새 글은 얕은 주제 폴더와 읽을 수 있는 파일명으로 저장합니다. 일치하는 기존
태그와 얕은 폴더가 있으면 재사용하고, 없으면 작은 한·영 키워드 규칙으로
개발·운영·연구·제품·학습 주제나 General을 선택합니다. 새 AI 호출은 없습니다.
최대 네 주제의 MOC가 동일 문서를 연결하며 새 목차는 MOC/에 만듭니다.
문서도 목차로 연결합니다. 기존 목차의 사용자 본문은 보존하고 관리 링크는
중복 없이 갱신합니다. 대소문자를 무시한 파일명 충돌에는 안정적인 접미사를 붙입니다.

기존 해시 파일명을 포함한 발행 경로는 자동 이동하지 않습니다. 이후 명시적
재발행은 동일 문서 ID·경로를 보호된 쓰기로 갱신하며 이전 내용은 archive
revision에 보관합니다. 문서와 MOC 쓰기는 기존 journal 복구·색인 확인 경로를
공유합니다. 주제 분류는 편의를 위한 규칙이며 의미 검증이 아닙니다. 주제가
바뀌어도 과거 MOC 링크를 파괴적으로 삭제하지 않습니다. 실제 보관함의 대량
이동이나 사용자별 분류 검토는 별도 작업입니다.

### 나침반 완료 목록의 발행 표시

나침반 → 완료 목록은 Knowledge 상태를 **미발행**, **발행 제안 중**,
**발행 완료** 칩으로 표시합니다. 생성·수정 요청이 대기·실행 중이거나 현재
수정 제안이 아직 적용되지 않았으면 발행 제안 중입니다. 실패·취소·대체·적용된
요청 자체는 대기 중인 제안으로 세지 않습니다. 생성된 비공개 초안은 **초안 검토
완료**로 정확한 저장 버전·내용 해시의 검토를 기록하거나 해당 버전을 발행할
때까지 검토 대기입니다. Task를 열기만 해서는 검토 완료가 되지 않습니다.
수정 제안 적용은 검토한 비공개 버전을 저장하며 발행하지 않습니다. 기존 발행
뒤 새 제안이 생기면 **발행 완료**와 **발행 제안 중**을 함께 표시합니다.

대기 중인 제안이 없는 미발행 Task의 **발행하지 않기…**는 확인 화면을 엽니다.
확인한 경우에만 별도 **Won’t publish** 태그를 추가하며 **되돌리기**로 제거할
수 있습니다. 선택은 재시작과 Task 다시 열기 후에도 유지됩니다. 기존 Task를
자동으로 발행 제외하지 않습니다. 이후 명시적인 발행이 성공하면 태그를
제거합니다. 확인 취소는 저장 상태를 바꾸지 않으며 오래된 상태나 저장 실패를
성공으로 표시하지 않습니다. 제목은 원래 Task를 열며 목록이 열린 동안 상태를
갱신합니다.
