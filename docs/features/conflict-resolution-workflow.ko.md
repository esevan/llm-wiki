# 충돌 해결 워크플로

[English](conflict-resolution-workflow.md) | **한국어**

Conflict Review는 AI 원문 보고서가 아니라 제안된 Solution 안에서 진행하는 결정 워크플로입니다. Vault 근거와 현재 Solution이 충돌하면 완료된 Queue 결과에 충돌별 카드가 표시됩니다.

각 카드는 핵심 비교를 가장 먼저 보여줍니다.

- 심각도와 짧은 분류
- 현재 Solution의 주장
- 충돌 대상 기존 문서·결정과 그 주장
- 예상 영향과 권장 해결안
- 펼쳐 볼 수 있는 출처와 원문

심각도는 High, Medium, Low 텍스트와 서로 다른 시각 표현을 함께 사용하므로 색상만으로 의미를 구분하지 않습니다. 근거는 필요할 때까지 접어 두며, Dialog 본문을 스크롤해도 검토 요약과 최종 동작을 계속 확인할 수 있습니다.

## 모든 충돌 해결하기

각 카드에서 사용자는 정확히 하나를 선택해야 합니다.

- **권장안 적용**은 Solution을 수정해야 한다고 기록합니다. 선택적으로 의견을 남겨 예정된 변경을 설명할 수 있습니다. Solution을 수정하고 최신 상태로 충돌 검토를 다시 통과할 때까지 충돌 상태를 유지합니다.
- **충돌 수용**은 충돌을 인지한 상태에서 현재 Solution 방향을 의도적으로 유지합니다. 나중에 예외의 맥락을 이해하고 재사용할 수 있도록 근거 입력이 필수입니다.

Footer는 전체·해결·미해결 개수를 보여줍니다. 모든 카드가 유효한 동작을 가지고 수용한 충돌마다 근거가 입력될 때까지 **계속** 버튼은 비활성화됩니다. 저장에 실패하면 Dialog를 닫지 않고 사용자가 입력한 결정을 그대로 유지합니다.

모든 충돌을 의도적으로 수용하면 LLM Wiki는 사용자의 명시적 해결 기록을 남기고 기존의 clear 충돌 Gate를 정상적으로 이어갑니다. AI는 충돌을 설명하고 해결안을 권장할 수 있지만 해결 방식을 선택하거나 Workflow 상태를 바꾸거나 출처를 만들어 낼 수 없습니다.

## 지속 가능한 기록과 호환성

LLM Wiki는 구조화된 충돌, 출처 근거, 선택한 동작, 근거, 해결 시각을 로컬 SQLite에 저장합니다. 검토를 다시 열면 `Conflict → Resolution → Rationale` 기록을 복원합니다. 이 로컬 검토 기록은 개인 작업 과정이며 자동으로 Knowledge에 게시하지 않습니다.

항목별 저장 기능이 생기기 전의 Queue 결과도 카드 형태의 기본값으로 읽을 수 있습니다. 다만 과거 보고서에서 해결 방식을 저장하려면 최신 검토를 다시 실행해야 합니다. 충돌이 없는 결과는 기존의 간결한 clear/conflicted 결정 경로를 유지하며 빈 카드를 추가하지 않습니다.
