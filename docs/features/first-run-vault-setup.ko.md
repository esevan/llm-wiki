# 최초 실행 Vault 설정

[English](first-run-vault-setup.md) | **한국어**

완전히 새로 설치한 LLM Wiki는 먼저 세 장면의 시작 애니메이션을 보여 줍니다. 현재 모니터 크기의
투명하고 테두리 없는 별도 창이 중앙의 애플리케이션 창 위를 반투명 애니메이션으로 덮기 때문에 일반
애플리케이션 dialog가 아니라 desktop 연출처럼 보입니다. 같은 React/CSS 연출이 macOS와 Windows에서
동작하며, 운영체제의 동작 줄이기 설정이 켜져 있으면 자동 장면 전환과 장식 animation을 끕니다.

이 소개는 최초 한 번만 나타납니다. **소개 건너뛰기**와 **Vault 선택**은 모두 소개 완료 상태를
영구 저장하고 운영체제의 네이티브 폴더 선택기를 엽니다. 다시 보기 설정이나 menu는 의도적으로
제공하지 않습니다. React에는 임의의 파일시스템 경로를 제출할 권한을 제공하지 않습니다.

선택기를 닫으면 소개를 다시 재생하지 않고 Vault 설정 화면으로 돌아가며 설정 미완료 상태를
유지합니다. Documents의 기본 폴더를 조용히 만들거나 채택하지 않습니다. 폴더를 선택하면 네이티브
애플리케이션이 다음을 수행합니다.

1. 선택한 위치가 실제 디렉터리인지 검증합니다.
2. 정규화한 경로를 `~/.llm-workbench/settings.json`에 저장합니다.
3. 선택한 Vault로 애플리케이션을 재시작합니다.
4. 번들 임베딩 모델로 Markdown을 백그라운드에서 색인합니다.

SQLite 워크플로 데이터베이스는 플랫폼의 앱 데이터 폴더에 그대로 보관되며 애플리케이션 설정을 더
이상 관리하지 않습니다. Vault 문서는 사용자가 선택한 폴더에서 이동 가능한 Markdown으로 유지됩니다.
명시적 Vault 설정이 없는 기존 설치는 이전
`Documents/LLM Wiki Vault` 위치를 승계하므로 마이그레이션 선택 화면이 나타나지 않습니다.
소개 중 앱을 종료한 경우 사용자가 건너뛰거나 완료할 때까지 다음 실행에서 다시 이어집니다. 기존
설치에는 소개도 나타나지 않습니다. `LLM_WIKI_VAULT`는 개발·테스트를 위한 명시적 override로
유지됩니다.

이전에 선택한 디렉터리를 더 이상 사용할 수 없으면 저장된 경로에 대체 폴더를 만들지 않고 이 설정
화면으로 돌아옵니다. 외장 또는 동기화 Vault의 연결이 끊겼을 때 빈 경로를 조용히 색인하지 않습니다.

온보딩 이후 Vault 변경은 실행 중인 색인, 충돌, 진행 중 작업 정책까지 함께 정해야 하므로 이 최초 실행
흐름의 범위에 포함하지 않습니다.
