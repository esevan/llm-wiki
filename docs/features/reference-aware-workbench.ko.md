# 근거를 반영하는 작업 초안

**한국어** | [English](reference-aware-workbench.md)

![중복 정의 없이 작업 초안과 대화를 보여주는 다듬기 탭](images/integrated-preview.ko.jpg)

*전체 App·합성 데이터의 비영구 WKWebView 캡처입니다. 설치 앱 캡처가 아닙니다.*

새 프리뷰는 설명에 수행할 일을, 목표에 의도한 결과를 담습니다. 배경·범위·접근 방법은
설명을 반복하지 않고 별도 정보가 있을 때 채웁니다. 중요한 제약, 완료 기준, 가정과
정확한 출처 연결은 유지합니다. 기존 저장 버전과 명시적인 적용 검사는 바뀌지 않습니다.

프리뷰의 계획 수립과 최종 작성은 AI 설정의 공통 **AI 요청 Timeout (초)** 값을 사용합니다(기본 180초, 범위 1–3600초). 제한에는 전체 응답 본문 수신이 포함됩니다. 두 단계는 로컬 검색을 사이에 두고 순차 실행되므로 전체 프리뷰 생성은 요청당 제한을 넘을 수 있습니다. 큐 대기는 이 제한에 포함되지 않습니다. 저장한 값은 재시작 없이 새 요청부터 적용됩니다. 타임아웃이 발생하면 작업은 실패 상태가 되어 명시적으로 재시도할 수 있으며, 프리뷰 생성은 자동 재시도하지 않습니다.

정제는 검색 계획, 관련 로컬 Vault 근거, 구조화된 최종 초안 순서로 작업 제안을
준비합니다. 완전한 검색 계획이 필요한 검색을 요청한 경우 초안을 저장하기 전에 검색을 끝냅니다. 부족한 근거는
가정으로 표시하며 검색 불필요, 검색 결과 없음, 작업 실패를 구분합니다.
정식 Task는 사용자가 명시적으로 적용한 뒤에만 변경됩니다.

생성된 초안은 설명, 배경, 목표, 범위, 범위 제외 사항, 제약, 완료 기준, 초기 접근법,
가정을 저장합니다. 사용한 주장에는 정확한 문서 버전과 절이 연결됩니다.
문서를 찾았다는 이유만으로 사용하거나 채택한 것으로 기록하지 않습니다.
생성 중 출처, Task, 대화 또는 저장된 초안이 바뀌면 늦게 도착한 결과가 현재
초안을 교체하지 못합니다.

선택적 조사는 대화와 독립적으로 실행되며 무한히 재시도하지 않습니다.
근거를 중요, 보충, 참고로 구분합니다. 현재의 중요·보충 결과는 다음 답변에
한 번 전달할 수 있고 참고 근거는 참조 데이터에 남습니다. 새 대화가 시작되면
완료되지 않은 이전 조사는 오래된 맥락으로 처리됩니다.

네이티브 애플리케이션은 변경 불가능한 초안 버전의 조회, 비교, 편집, 복원을
지원합니다. 복원은 새 초안을 추가하며 Task 이력은 바꾸지 않습니다.
명시적 적용은 현재 초안, 내용 해시, Task 버전, 대화, 계층, 출처를 하나의
트랜잭션에서 확인합니다. 확인에 실패하면 사용자 작업을 보존합니다.
다듬기 화면을 열었을 때 초안이나 진행 중인 작업이 없으면 첫 초안을 자동으로
준비합니다. 대화를 계속하는 동안 저장된 초안과 백그라운드 결과를 갱신합니다.
편집은 시작한 버전과 내용 해시를 유지하므로 새 결과가 저장하지 않은 편집을
덮어쓰지 못합니다. 화면을 떠나기 전에 편집을 저장하거나 취소하고, 현재 초안을
확인한 뒤 Task에 적용하세요.

메시지 입력창에서 @를 입력하면 로컬 문서와 절을 검색합니다. 화살표 키와 Enter로
정확한 멘션을 삽입할 수 있으며 자동 전송되지 않습니다. 보내기 전에 텍스트와
멘션 연결을 저장하고 다듬기를 다시 열면 복원합니다. 전송한 멘션만 대화 맥락에
포함됩니다. 결과가 없어도 참조 검색을 계속할 수 있고 새 결과가 도착해도 직접
사용자가 새 참조를 확인하거나 필터·정렬을 바꾸기 전에는 읽던 순서를 유지합니다. 참조 확인은 입력창을 막지 않고 제한된
선택적 조사를 시작합니다. 색인에 반영된 파일 이동 뒤에도 정확한 출처를 열 수
있으며 이전 내용이 없으면 재시도 가능한 오류를 표시합니다.

[기능 명세](../../specs/019-reference-aware-workbench/spec.md)와
[네이티브 어댑터 계약](../../specs/019-reference-aware-workbench/contracts/application-api.md)을 참고하세요.

참조 뷰어는 뒤로·앞으로 이동할 때 문서 버전과 절의 정확한 연결을 유지합니다.
불러오기 실패 시 재시도할 수 있으며 닫으면 출처 버튼으로 포커스가 돌아갑니다.
버전 비교는 저장된 두 버전을 명시적으로 요청합니다. 이전 버전 복원과 Task 적용은
서로 다른 사용자 작업입니다.

참조는 정확한 문서 버전별로 절을 묶어 한 페이지에 문서 20개씩 보여 줍니다.
검색어, 상태, 근거 관점, 정보 유형, 기록된 사용 상태로 필터링할 수 있으며 결과가
없어도 필터는 유지됩니다. 새 문서와 절은 ‘새 참조 보기’로 확인하거나 필터·정렬을
바꿀 때 목록에 반영됩니다. 비동기 도착만으로 읽던 행의 순서를 바꾸지 않습니다.

검색 결과를 여러 개 선택한 뒤 ‘선택한 멘션 삽입’을 누르면 선택 순서대로 입력됩니다.
입력창에서 Enter 또는 Space를 누르면 현재 결과를 전송 없이 삽입합니다. 같은 제목도
출처 ID와 버전으로 구분합니다. Backspace/Delete는 연결된 토큰 전체를 제거하며,
토큰 내용을 편집하거나 일반 텍스트를 붙여 넣어도 출처 연결을 새로 만들지 않습니다.
초안은 가정의 저장된 상태와 근거를 따로 표시하며, 참조 필터에서도 열람·멘션·사용·
채택·제외 기록을 구별합니다.

실제 사용 기록은 Capture의 수락 또는 적용 결정으로 생성한 Task에 이어집니다.
원본 Capture가 같다는 이유로 다른 Task에 참조를 공유하지 않습니다. Knowledge는
정확한 문서 버전과 절을 유지하고, 사용 및 반증 기록을 해당 근거가 뒷받침한 저장된
문장과 함께 묶습니다. 열람, 멘션, 검색 발견만으로 게시 링크를 만들지 않습니다.
사용자가 제외한 출처는 다시 사용으로 표시하기 전까지 제외되며, 자동 생성이나
채택으로 제외를 취소하지 않습니다.

## 부분 생성 preview

누락된 선택 문자열·목록은 로컬에서 보완합니다. Task 필드가 누락되면 preview 복원 후 적용할 때도 기존 저장값을 유지합니다. 누락을 이유로 기존 제목·상세·범위·제외 범위·완료 기준을 지우지 않습니다. 설명·목표 누락은 정확한 기존 Task 값으로 보완할 수 있습니다. Capture 원문은 미정제 설명으로 사용할 수 있지만 목표를 만들 수 없으면 미완성으로 남깁니다.

검색 판단이 불완전하면 검색을 건너뛰고 근거 범위를 미확인으로 표시하며, 검색 불필요로 단정하지 않습니다. 선택적 추가 조사 누락은 해당 조사만 생략합니다. 부분 preview에는 사용자가 검토할 진단을 표시합니다. 잘못된 타입·제시된 출처의 모순·근거 없는 source 가정 연결은 계속 오류로 처리합니다. 모델 호출·재시도를 추가하지 않으며 계획·최종 작성은 각각 한 번의 요청을 사용합니다.

생성된 preview 텍스트의 필드별 한도는 UTF-8 바이트가 아닌 유니코드 문자 12,000개입니다. 오류는 해당 필드를 명시하고 JSON 타입 오류와 길이 초과를 구분합니다. 누락 필드를 기존 Task·Capture에서 채운 경우에는 원문 전체를 유지하고 Task 수정 대상에서 제외하며, 모델 출력 한도에 맞추기 위해 원문을 조용히 자르지 않습니다.

구조화 프리뷰 요청은 이제 provider에 strict JSON Schema를 전달합니다. `description`, `background`, `goal`, `scope`, `nonGoals`는 문자열이고, `constraints`, `completionCriteria`, `initialApproach`는 문자열 배열입니다. 프롬프트에는 여러 줄 scope를 문자열로 쓰는 예시가 포함됩니다. scope 배열을 반환하면 여전히 타입 오류이며, 조용히 합치거나 채택하지 않습니다. provider의 응답 거부나 미완료 출력은 프리뷰 적용 전에 알립니다. 기존 선택 필드 누락 복구와 사용자의 명시적 Apply는 유지합니다.

프리뷰 근거 연결에는 요청별 참조 ID를 사용합니다. 검색 결과와 명시적 문서 언급을 합친 뒤 ID를 부여하며, provider 스키마는 해당 요청의 ID만 허용합니다. 앱은 요청 스냅샷에서 정확한 문서·버전·섹션을 복원한 후 기존 주장·가정·버전·트랜잭션 검증을 수행합니다. 알 수 없는 ID, 동일 주장·참조의 중복 연결, 잘못된 참조는 근거를 삭제하지 않고 실패로 처리합니다. 참조가 없으면 claimSources는 비어 있어야 합니다. 추가 모델 호출이나 자동 재시도는 없으며 Knowledge의 정확한 출처·인용 계약은 유지합니다.

정제에서는 Task 제목과 설명을 별도로 다룹니다. 채팅으로 제목 변경을 요청하거나 프리뷰 편집에서 직접 수정할 수 있습니다. 새 제목·변경한 Task 제목은 1-70개의 Unicode 스칼라 값으로 제한하며 JSON Schema·Rust·화면이 같은 기준으로 셉니다. 140바이트 제한이 아닙니다. 한글 음절과 일반 emoji는 각각 하나이며 결합 문자·연결 emoji는 여러 값으로 셉니다. 길이를 초과한 입력도 그대로 보존하며 저장·적용을 막습니다. 다른 필드만 수정할 때 기존 Task 제목은 보존합니다. 별도 제목이 없는 이전 프리뷰는 원래 내용과 hash를 바꾸지 않고 설명 전체를 호환 제목으로 표시합니다. 길이를 초과하면 제목을 줄여 저장한 뒤 적용하세요. 제목 제한을 위한 추가 AI 호출이나 자동 재시도는 없습니다.

Task에 적용하면 검토한 버전 저장·정제 완료 표시·정제 세션 완료가 같은 트랜잭션에서 처리됩니다. Workbench는 정제 화면을 닫고 목록을 갱신한 뒤 적용 결과의 Task를 엽니다. Capture가 Task로 전환되는 경우에도 동일하며 기존 Task의 ID는 유지합니다. 적용 실패 시 프리뷰를 유지하고 저장 후 새로고침 문제를 저장 실패로 표시하지 않습니다. 출처·프리뷰·맥락·Task 버전 검증은 유지합니다.

일반 Task 수정은 변경하지 않은 기존의 70글자 초과 제목을 유지할 수 있습니다. 정제 적용은 이전 프리뷰나 AI 누락 복구 제목도 70글자 이하여야 하므로, 제목을 명시적으로 줄여 저장한 뒤 적용하세요.

### 검색 계약과 초안 저장

검색하지 않는 계획은 검색어가 비어 있고 재검색은 null이어야 합니다. 검색 계획은 공백이 아닌 검색어 1-4개와 재검색어 최대 2개를 사용하며 각 검색어는 유니코드 문자 500개로 제한됩니다. 지원하지 않는 aspect는 실행 전에 거부합니다. 제어 필드가 없는 이전 응답은 근거를 만들거나 모델을 재시도하지 않고 미검증 상태를 명시합니다.

프리뷰 편집 저장이 승인되면 조회에 실패해도 저장된 버전을 유지합니다. 조회 실패를 별도로 표시하며 다음 편집에는 저장된 버전과 해시를 사용합니다. 근거 스냅샷이 없는 이전 Knowledge 초안은 읽기 전용입니다. 근거에 연결된 내용을 편집하려면 새 초안을 생성하세요.

Knowledge 수정 저장이 승인된 뒤 조회가 실패하면, 승인된 본문을 별도로 유지하고 읽기 전용 복구 화면을 표시합니다. 정본의 Task 식별자·버전·본문 해시·본문을 확인하기 전에는 편집·복원·검토 메모·발행을 제공하지 않습니다. 복구 재시도는 조회만 수행하며 수정 저장을 반복하거나 근거 정보를 만들어 내지 않습니다. Task 전환 뒤 도착한 이전 Task 응답은 새 화면에 적용하지 않습니다.

검색 불필요·적합한 결과 없음 같은 일상적인 검색 판단과 기술 진단은 접힌 **참조 검색 상세**에서 확인합니다. 검색 미확인·실패, 부분 초안 안내와 중요한 누락 사항은 계속 본문에 표시합니다. 제목 길이 오류는 유효하지 않은 현재 제목에만 해당 필드 옆에 표시하며, 유효한 제목에는 오류 안내를 표시하지 않습니다.

Workbench 카드는 데스크톱에서 320px 폭을 유지하며 레인이 더 좁을 때만 줄어듭니다. 레인은 작업 공간에 맞게 줄바꿈됩니다. 각 레인의 카드 목록은 화면 높이에 맞춰 제한된 독립 세로 스크롤 영역이며 키보드로 포커스할 수 있습니다. 제목은 스크롤 영역 밖에 유지되고, 페이지 스크롤로 다른 카테고리에 접근할 수 있습니다.

Workbench 카드는 데스크톱에서 320 × 240px 크기를 유지합니다. 각 레인은 카드 폭을 늘리지 않고 가용 폭에 따라 카드 열 수를 늘리며 독립 세로 스크롤을 유지합니다. 제목과 처음 남긴 내용은 최대 두 줄과 말줄임으로 표시하며 하단 버튼 위치를 통일합니다. 전체 원문은 Task 상세 또는 Capture 다듬기에서 확인할 수 있습니다. Subtask 버튼은 부모 Task 상세를 열며, 상세의 계층 목록에서 하위 작업을 펼쳐도 보드 카드 크기는 바뀌지 않습니다.

프리뷰는 요약·목표·완료 기준을 먼저 보여주고 범위·제약·진행 계획은 접어서 확인합니다.
편집과 비교는 모든 기존 필드를 보존합니다. 사용자가 적용하면 완료 기준을 같은 트랜잭션에서
Task의 미체크 체크리스트로 추가합니다. 생성만으로 Task를 바꾸지 않습니다. 내용 기반 ID로
재적용·순서 변경의 중복을 방지하고 기존 체크·수동 수정·수동 추가 항목은 덮어쓰거나 삭제하지
않습니다. 문구가 바뀐 기준은 새 미체크 항목으로 추가하고 이전 항목을 보존합니다. 체크는
사용자의 항목 상태이며 실행 성공이나 근거 검증을 증명하지 않고 Task 완료·발행도 하지 않습니다.

넓은 Refinement 화면은 왼쪽의 큰 읽기 카드에 프리뷰를 표시하고, 오른쪽 위에는 기존 대화, 아래에는 짧은 근거 제목과 발췌를 배치합니다. 전체 출처 필터는 근거의 접힌 도구에서 사용할 수 있습니다. 읽기 영역과 보조 열은 독립적으로 스크롤되며, 좁은 창에서는 프리뷰·대화·근거 순으로 이어집니다.

프리뷰 모달과 메인 읽기 카드는 초광폭 화면에서도 창 너비에 맞춰 늘어납니다. 유동적인 표면 안에서 본문 줄길이만 제한하며, 기존 대화와 근거는 보조 열을 유지합니다.

프리뷰는 메인 읽기 영역을 유지하며 기존 대화·근거 열을 데스크톱에서 340–720px 범위로 넓힙니다. 좁은 창에서는 프리뷰 아래로 이어집니다. Task 다듬기는 생성된 프리뷰 아래에 저장된 정의를 중복 표시하지 않습니다. 생성된 프리뷰가 없으면 같은 위치에서 기존 Task 내용을 읽고 편집할 수 있습니다. 이전에 열어 둔 정의 편집은 저장하거나 취소할 때까지 복구할 수 있습니다.

## Task 생명주기와 완료 이력

다듬기 탭은 기존 세션을 읽으며, 적용된 정제 세션을 다시 활성화하지 않습니다. 프리뷰 생성과 후속 정제 대화는 별도 생명주기를 가집니다. 정제가 적용된 Task는 명시적인 Task 상태 변경 전까지 정제된 Task 목록에 유지됩니다. 처음 접수된 Task의 초기 정제 흐름은 계속 사용할 수 있습니다.

완료된 Task에서는 과거 정제 대화, 저장된 프리뷰 버전, 비교, 참조와 세션을 읽을 수 있습니다. 새 정제 메시지, 프리뷰 생성·편집·복원·적용은 차단하며, 완료 이후 도착한 결과도 적용하지 않습니다. Task 정의, 체크리스트 상태, 결정, 연결과 기존 작업 로그는 읽기 전용입니다. 별도 Knowledge 초안 수정·검토·발행은 계속 사용할 수 있습니다. 명시적으로 다시 열면 원래 완료 기록을 보존한 채 새 작업을 진행할 수 있습니다.
