# 맥락을 보존하는 Refinement

[English](refinement-preview-status.md) | **한국어**

Refinement는 Capture나 Task의 원래 맥락을 유지하면서 검토 가능한 작업으로 다듬는 과정입니다.
Capture에 해결책이 이미 있다면 처음부터 다시 찾을 필요가 없습니다. 단순한 업무는 바로 Task로
등록할 수 있으며, 정제나 Problem 승인은 필수 단계가 아닙니다.

## 캡처와 정제의 이미지 첨부

캡처와 정제 메시지는 입력마다 여러 이미지를 지원합니다. **이미지 첨부**로 파일을 선택하거나
입력창에 클립보드 이미지를 붙여넣으세요. 장당 10 MB 이하의 PNG, JPEG, GIF, WebP를 지원합니다.
전송 전에 미리보기와 파일명을 확인하고 **이미지 제거**로 해당 이미지의 첨부를 취소할 수 있습니다.
이미지가 있으면 텍스트 없이도 저장·전송할 수 있으며, 이미지를 추가로 선택하거나 붙여넣으면 기존 첨부에 더해집니다.

저장한 이미지는 로컬 데이터베이스에 보존되고 정제를 다시 열면 표시됩니다. 원본 캡처와 대화에
첨부한 이미지는 정제 답변과 제안 생성 시 설정된 AI 제공자에게 전달되므로 이미지 입력을 지원하는
모델이 필요합니다. 제공자 오류는 화면에 표시되고 저장한 이미지는 보존됩니다. 보내지 않은 정제
이미지는 앱을 종료하기 전까지 정제 창을 닫았다 열어도 유지되며, 전송 실패 시에도 첨부를 유지합니다.

이미지만 있는 캡처를 저장하면 AI가 이미지의 텍스트, 표, 핵심 내용을 자동으로 분석하고 1차 정제 프리뷰를 준비합니다. 추가 메시지 없이 정제를 열어 결과를 검토할 수 있습니다. 이전에 저장한 이미지 전용 캡처도 대화 이력이 없으면 정제를 처음 열 때 분석을 시작하며, 다시 열어도 중복 실행하지 않습니다. 불확실한 내용은 추측하지 않고 표시하도록 요청하며, 제안 적용은 사용자가 결정합니다.


## 정제 패널에서 작업하기

Capture나 Task의 **Refine**을 열거나 Workbench의 저장된 정제 바로가기에서 이어갑니다.
정제는 집중 대화상자에서 열립니다. 왼쪽에는 스크롤할 수 있는 제안 결과를, 오른쪽에는 전체
대화 이력과 입력창이 있는 채팅 영역을 함께 표시합니다. 대화상자가 열려 있는 동안에는 나머지
Workbench를 사용할 수 없습니다. 창을 닫으면 대화상자가 제거된 뒤 키보드 포커스를 복원합니다. 도킹된 대화의 Context 컨트롤은 프리뷰 선택과 독립적으로 맥락을 펼치거나 접습니다. 도킹된 대화에서는 답변 수신이 끝나면 텍스트 표시 애니메이션을 기다리지 않고 다음 메시지를 보낼 수 있습니다. 제안 결과와 함께 작업 메모를 남길 수 있으며, 저장된 메모·스크롤
위치·대화 이력을 통해 나중에 이어갈 수 있습니다.

**Send** 또는 `Enter`로 메시지를 보내고, `Shift+Enter`로 줄바꿈합니다.
`Ctrl+Enter`, `Cmd+Enter`로도 보낼 수 있습니다.
현재 메시지 전송이나 응답 처리가 진행 중일 때는 Send를 사용할 수 없습니다. 일시적인 초안이
지워진 뒤에도 매 AI 요청에는 원본 Capture와 순서가 유지된 대화 이력이 포함됩니다.

대화상자는 안정적인 읽기 높이를 유지하고 창에서 사용할 수 있는 높이를 넘으면 대화 영역만
스크롤합니다. 입력창은 채팅 영역 맨 아래에 유지됩니다. 짧은 대화도 입력창 바로 위에 배치되며,
새 메시지가 아래에 추가되면 이전 대화는 위로 올라갑니다. 응답을 준비하는 동안에는 접근 가능한 지역화 상태와
움직이는 줄임표를 표시합니다. 현재 Refinement API는 폴링 후 완성된 도우미 메시지를 반환하므로,
새 메시지가 도착하면 화면에서만 점진적으로 나타내는 연출을 적용합니다. 저장된 대화 이력은 즉시
표시하며 다시 재생하지 않습니다. Refinement 대화상자를 열어 둔 동안에는 대화상자를 닫을 때까지
Workbench의 배경 스크롤 위치가 고정됩니다.

백그라운드 프리뷰는 여러 제안을 만들 수 있습니다. 각 제안을 따로 검토하고 수정·수락·거절합니다.
한 제안을 수락해도 다른 제안까지 수락되지는 않습니다. 채팅 답변과 제안 조회는 독립적으로 진행되며, 늦게 도착한 최신 제안도 표시됩니다.
Task 제안 프리뷰는 제목·세부 정보·결과·범위·하지 않을 일·검증 기준을 포함한 의미 있는 결과
필드를 모두 표시합니다. 응답이 세부 정보를 `body` 필드로 반환하거나 결과를 중첩해도 동일하게
보여 줍니다. 제안을 수락하면 이 값들이 Task 세부 정보로 보존됩니다.

## 같은 Task 정제와 진행 중인 작업 Focus

정제 적용은 기존 Task ID를 유지하고 정의 리비전을 추가합니다. Capture의 첫 정제는 같은 ID를 유지한 Task 전환이며,
이후에는 그 Task를 계속 정제합니다. 원본 Capture는 받은 항목에서 빠지고 카드와 상세의
**처음 남긴 내용**으로 보존됩니다. Task를 다시 다듬으면 원래 Capture의 대화를 이어갑니다.
기존 버전에서 다른 ID로 만들어진 Task는 ID를 바꾸지 않고 기존 원본 연결을 사용합니다. 기존 Task 세션에서 AI가 “새 Task”로 응답하더라도 Task 수정으로
처리하므로 적용할 때 무관한 복사본을 만들지 않습니다. 적용 후 **프리뷰** 옆의 **작업 상태** 탭이
열리고 **Refined - Revision N**을 표시합니다. 정제 여부와 실행 상태는 별개입니다. **작업 시작**으로
진행 중 상태로 바꾸면 Workbench 캡처 폼 바로 아래에 나타납니다. 적용한 세션은 다듬는 중 바로가기에서 빠집니다.
**진행 중인 작업에 Focus**는 선택과 입력을 보존하면서 다른 영역을 숨깁니다.

## 명시적인 Subtask

사용자가 독립적으로 완료할 업무를 분리해 달라고 요청할 때만 Subtask를 제안합니다.
**하위 작업으로 분리** 버튼으로 명시적으로 적용하며, 일반 정제 적용으로 새 하위 작업을 만들지 않습니다.
API에서도 Subtask 적용에는 최상위 `intent: "split"`이 필요합니다. 프리뷰에 분리 이유, 부모, 범위,
하지 않을 일과 검증 기준을 표시합니다. 적용은 아래 부모 Knowledge 자동 갱신·발행 흐름에도 동의하는
동작입니다. 부모와 자식은 펼치기와 들여쓰기로 표시하고, Task 상세에서는 부모·형제·자식으로 이동할
수 있습니다. 기존 `split_from` 링크는 출처 관계로 유지하며 소유 계층으로 바꾸지 않습니다. 계층에
속한 Task는 완료·Knowledge 근거를 보존하기 위해 삭제를 제한합니다.

정제 요청에는 부모·형제·자식 Task의 범위와 하지 않을 일을 함께 제공합니다. 가족 Task가 바뀌면
기존 제안 적용을 거부하고 다시 정제하도록 합니다. 다른 Subtask 제안을 먼저 적용했을 때도 새
경계를 참고한 뒤 다음 분리를 적용합니다.

Subtask를 근거와 함께 완료할 때마다 부모에 누적 Knowledge 리비전을 만들고 **같은 부모 Vault 문서에
자동 발행**합니다. 남은 Subtask는 열린 상태를 유지하고, 모두 완료되면 부모도 자동 완료합니다.
중첩된 부모의 완료도 상위 부모에 반영합니다. 자식을 다시 열면 완료된 조상 Task도 진행 중으로
돌아가며 이전 완료 근거와 Knowledge 리비전은 보존합니다.

완료 기록과 로컬 Knowledge 리비전 생성은 함께 저장하므로 동일 완료 요청을 재시도해도 중복되지
않습니다. 발행 대기 기록은 유지되고 Task를 다시 열거나 앱을 재시작하면 재시도합니다. Vault 파일의
외부 수정은 덮어쓰지 않으며 부모에 발행 오류를 표시합니다. 기존 파일을 복원하거나 수정 충돌을
해결한 뒤 발행을 재시도합니다.

## 중단과 오류 처리

- 제공자나 제안 조회에서 오류가 나면 화면에 표시하고, 이미 저장한 맥락은 보존합니다.
- 세션·작업 상태·제안 조회에 실패하면 **다시 시도**로 저장된 결과를 다시 불러옵니다.
  AI 요청을 다시 보내지 않으며, 작성 중인 메시지와 작업 메모는 패널에 유지합니다.
- AI 응답 실패가 확인되면 열려 있는 패널에서 보냈던 메시지를 비어 있는 입력란에 복원합니다.
  사용자가 내용을 확인하고 다시 보낼 수 있습니다.
- 세션을 연 뒤 상태 확인에는 읽기 요청을 사용하며, 앞선 요청이 끝난 후 다음 요청을 보냅니다.
- 정제의 DB 쓰기는 상태를 읽기 전에 쓰기 권한을 확보하고, 경합 시 제한된 시간 동안
  기다립니다. 오래된 조회 상태를 쓰기로 전환하면서 생기는 잠금 오류를 방지합니다.
- 닫을 때 작업 메모와 위치를 저장합니다. 저장에 실패하면 오류와 메모를 유지한 채 패널을
  열어 두므로 닫기를 다시 시도할 수 있습니다.
- 제공자 작업 중 패널을 닫아도 서버의 작업 자체를 취소하지는 않습니다. 늦게 도착한 응답은
  다른 항목을 덮어쓰지 않으며, 원래 항목을 다시 열어 저장된 결과를 확인할 수 있습니다.
- 저장에 성공한 정제 작업은 앱을 다시 실행한 뒤에도 저장된 작업 공간에서 이어갈 수 있습니다.


### 채팅과 프리뷰의 독립 실행

채팅 요청은 먼저 짧은 답변을 생성합니다. 답변이 저장되면 다시 메시지를 보낼 수 있습니다.
전체 제안 생성은 AI 작업 큐의 **다듬기 프리뷰**로 별도 실행되며 진행 상태·취소·재시도를
독립적으로 관리합니다. 프리뷰가 업데이트되는 동안에도 다음 메시지를 보낼 수 있습니다.
프리뷰가 실패해도 저장된 채팅 답변은 유지됩니다. 큐에서 재시도하거나 새 메시지를 보내세요.

새 메시지를 보내면 이전 프리뷰 작업은 오래된 결과로 처리됩니다. 이전 대화의 늦은 결과가
최신 프리뷰를 덮어쓰거나 적용되지 않습니다. 대화상자를 닫아도 백그라운드 작업은 계속되며,
다시 열면 상태를 복원합니다. 생성 도중 앱이 종료되면 재시작 후 큐에서 중단된 프리뷰를
재시도할 수 있습니다. 실제 변경에는 계속 명시적인 검토와 적용이 필요합니다.

## 키보드 동작

Refinement와 Task 상세에서 Tab과 Shift+Tab은 저장된 메모 펼치기를 포함해 최상위 대화상자
안에 머뭅니다. 포커스가 밖으로 나가거나 입력 요소의 비활성화·제거로 사라지면 안으로 복구합니다.
`Escape`는 포커스가 페이지 배경으로 빠져도 최상위 대화상자에서만 처리하며 키의 기본 동작을
차단합니다. Task 상세의 로딩·불러오기 오류 화면에서도 적용되며, Task 변경 처리 중 닫기가
제한되어도 키 입력은 차단합니다. 저장하지 않은 Task 변경은 기존 확인 절차를 유지하고,
Refinement는 초안 저장 후 닫히며 저장 실패 시 열린 상태로 남습니다. 닫으면 가능한 경우 열었던
요소로 포커스를 돌립니다. 네이티브 확인창과 IME 조합 중 Escape는 각각의 기존 처리를 유지합니다.
`Enter`, `Cmd+Enter`, `Ctrl+Enter`는 IME 조합 중에는 보내지 않습니다. 실제 macOS 전체 화면, 한국어 IME,
VoiceOver 동작은 수동 검증 대상입니다.

## 이전 Problem 기록 이어가기

이전 흐름에서 만들어진 Problem 전용 기록도 **Refine**으로 열 수 있습니다. 이 대화에는 기존
Context/Detail Preview가 표시됩니다. Preview 상태를 누르면 Context가 열리고, 불러오기에
실패하면 재시도 동작이 표시됩니다. 생성된 Preview는 검토한 뒤에 적용합니다.

내용을 적용하면 새 Problem 리비전이 만들어집니다. 대화도 새 리비전을 따라가며, 이후 검토해서
만든 Task에는 해당 Problem의 정확한 리비전이 출처로 연결됩니다. 오래된 변경은 최신 내용을
덮어쓰지 않고 거절합니다. 대화 추적과 Task 제안 수락은 계속 사용자가 결정하며, 이전 Problem
승인이나 Solution 생성 단계는 필요하지 않습니다.

이전 **Explore next Solution**, **Create Problem** 모달 경로는 현재 Task Workbench의 진입점이
아니며, 새 작업이 반드시 거쳐야 할 단계를 정의하지 않습니다.

## 검증 범위

자동 시나리오는 순서대로 이어지는 멀티턴 요청, Capture 맥락 보존, 제안 결정, 재시도, 중단·재개,
정확한 Problem 출처 연결을 검사합니다. 로컬 결정적 제공자로 요청 내용과 기능 동작을 검증하며,
이를 실제 AI 모델의 답변 품질이나 지연 시간 검증으로 간주하지 않습니다.

실제 패키지 실행 결과와 제외 근거는 [인터랙티브 기능 검증 기록](../testing/interactive-coverage.md),
전체 흐름은 [Task 중심 Workbench 안내](conflict-gated-workflow.ko.md)를 참고하세요.
