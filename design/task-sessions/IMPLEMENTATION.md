## Implemented scope

- Existing session create/prepare/manual Run/resume/import/link, exact provider request routing, stream event barrier/generation checks, final-report transaction, Work Log provenance and separate Knowledge paths are reused.
- Manual title editing and single-option provider form removed. Automatic display labels use saved user request/note text with existing title fallback; historical titles remain stored. Optional Task context, execution history, completed notes and environment are disclosures.
- Model/reasoning choices use provider model metadata. Unknown capabilities offer inheritance only; explicit unsupported effort is rejected. Model change warns and resets an invalid selection. Environment is session-scoped; active settings are read-only, bound-folder changes stay protected by existing preparation validation. Codex-home metadata remains a separate read-only app setting.
- Additive schema v26 stores reasoning and durable per-session pending requests/controllers. Queue items capture immutable execution settings, resolved effort and consent/settings revision, plus instruction/attachment. Editing/reordering/removing uses item revisions. Native claim + Run/Work Log creation are one immediate transaction; the existing per-session unique active-Run index remains authoritative.
- Running composer enqueues instead of steering. Confirmed success advances one pending instruction at a time. Approval/input keeps the current Run active. Failure/ordinary Stop/uncertain outcome pauses the queue. Stop-and-drain records exact target intent before interrupt and waits for the provider terminal event; interrupt ACK is insufficient. Cancel drain pauses future starts without undoing interruption.
- Restart marks automatic queues review-required. Uncertain dispatched work is never automatically resent. Local idempotency does not promise exactly-once external side effects across a crash. Existing manual callers are kept separate; starting a manual Run while a queue exists pauses that queue for explicit review.
- Settings revision uses a dedicated epoch, not note timestamps. Same-value consent/config saves invalidate old queue settings. Both bind and dispatch recheck the epoch; queue claim checks the exact preparation revision and snapshot inside its transaction. A concurrent settings save cannot restore stale effort readiness. A note does not invalidate consent.
- Existing app-lifetime draft, attachment, formal answer and operation identities remain. Pending editor text is retained across modal close; if the item is claimed while editing, unsaved text remains visible as unapplied rather than being discarded or modifying active work. Completed history remains read-only; append-only notes and separate Knowledge work remain available. Pending requests must be removed before Task completion/hold.
